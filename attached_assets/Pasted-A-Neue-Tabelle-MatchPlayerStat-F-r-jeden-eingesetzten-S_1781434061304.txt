A. Neue Tabelle MatchPlayerStat

Für jeden eingesetzten Spieler wird pro Spiel genau ein Datensatz gespeichert.

Mögliche Felder:

class MatchPlayerStat(models.Model):
    match = models.ForeignKey(Match, on_delete=models.CASCADE)
    player = models.ForeignKey(Player, on_delete=models.CASCADE)
    club = models.ForeignKey(Club, on_delete=models.CASCADE)

    started = models.BooleanField(default=False)
    position = models.CharField(max_length=10)
    position_fit = models.CharField(max_length=2)  # HP, NP, FP

    minute_on = models.PositiveSmallIntegerField(default=0)
    minute_off = models.PositiveSmallIntegerField(default=90)
    minutes_played = models.PositiveSmallIntegerField(default=0)

    rating = models.DecimalField(max_digits=3, decimal_places=1)

    goals = models.PositiveSmallIntegerField(default=0)
    assists = models.PositiveSmallIntegerField(default=0)

    yellow_cards = models.PositiveSmallIntegerField(default=0)
    red_card = models.BooleanField(default=False)

    substituted_in = models.BooleanField(default=False)
    substituted_out = models.BooleanField(default=False)
    injured = models.BooleanField(default=False)

    class Meta:
        constraints = [
            models.UniqueConstraint(
                fields=["match", "player"],
                name="unique_match_player_stat",
            )
        ]

Die Unique Constraint ist wichtig, damit ein Match bei erneutem Speichern keine doppelten Spielerstatistiken erzeugt.

B. Speicherung direkt nach der Simulation

Ablauf:

Match simulieren
→ Resultat und Matchdaten speichern
→ Events speichern
→ MatchPlayerStat für alle eingesetzten Spieler speichern
→ PlayerSeasonStat aktualisieren
→ Tabelle aktualisieren

Das sollte in einer gemeinsamen Datenbanktransaktion laufen:

with transaction.atomic():
    save_match_result()
    save_match_events()
    save_match_player_stats()
    update_player_season_stats()
    update_table()

Scheitert ein Teil, wird das gesamte Speichern zurückgerollt.

Für Durchschnittsnoten sollte intern nicht nur der gerundete Durchschnitt gespeichert werden.

Besser:

rating_sum = models.DecimalField(...)
rated_appearances = models.PositiveIntegerField(...)
average_rating = rating_sum / rated_appearances

So entstehen keine Rundungsfehler durch wiederholtes Mitteln.

Mindestspielzeit für eine Note

Eine klare Regel ist nötig. Mein Vorschlag:

ab 15 Einsatzminuten normale Note
unter 15 Minuten nur Note, wenn ein relevantes Ereignis vorliegt:
Tor
Vorlage
Karte
Verletzung
entscheidendes individuelles Ereignis

Alternativ können alle Spieler eine Note erhalten, aber für Ranglisten sollte eine Mindestanzahl an Minuten oder Einsätzen gelten.

Da die Regression bereits Einwechslungen berücksichtigt, würde ich die Berechnung nicht mehr ändern. Nur die spätere Ranglistenqualifikation begrenzen.

3. Spieler des Spiels

Danach kann automatisch ein Man of the Match bestimmt werden.

Regeln:

beste Note gewinnt
bei gleicher Note mehr direkte Torbeteiligungen
danach mehr Einsatzminuten
danach deterministischer Match-/Spieler-Seed

Torhüter müssen ebenfalls gewinnen können.

Im Matchmodell könnte gespeichert werden:

man_of_the_match = models.ForeignKey(
    Player,
    null=True,
    blank=True,
    on_delete=models.SET_NULL,
)
4. Spielbericht erweitern

Der Spielbericht sollte dann eine echte Aufstellungstabelle erhalten:

Spieler	Pos.	Min.	Tore	Vorlagen	Karten	Note

Darstellung:

Startelf und Einwechselspieler getrennt
ausgewechselte Spieler mit Minute
eingewechselte Spieler mit Minute
Note 1,0–2,0 positiv hervorgehoben
Note 4,5–6,0 negativ hervorgehoben
Spieler des Spiels markiert
HP/NP/FP höchstens als Tooltip, nicht als störender Text

Die Daten dürfen nicht erneut aus dem Ticker rekonstruiert werden. Der Spielbericht liest direkt aus MatchPlayerStat.
