#507 - DFB-Pokal: Wettbewerb, Auslosung & Pokalbaum
What & Why
Task #501 hat die K.-o.-Engine (Verlängerung + Elfmeter) geliefert. Jetzt wird daraus ein vollständiger Pokalwettbewerb:

Wettbewerbe (Liga + Pokal) im Creator Mode anlegen
Bundesliga mit 14 Dummy-Clubs generieren (18 Bundesliga + 14 = 32 Teilnehmer, glatte 2er-Potenz, keine Freilose)
Deterministisches Auslosungsverfahren mit SHA-256-Seed (bereits vorhanden)
Saisonbasiertes Datenmodell: CupSeason → CupRound → CupFixture
Automatischer Rundenfortschritt inklusive vollständiger Post-Match-Pipeline
Pokalbaum-Ansicht im UI
Die Simulation läuft mit simulate_ko_match() plus allen Frische-/Verletzungs-/Statistik-Hooks. Der Ligaspieltag-Zyklus bleibt unberührt.

Done looks like
Im Creator Mode (Deutschland, Level-2) gibt es einen "Neuer Wettbewerb"-Button → DFB-Pokal anlegen
Bundesliga mit 14 Dummy-Clubs anlegen (idempotent, kein Duplikat bei erneutem Klick)
Jeder Dummy-Kader: 1 TW, 1 LV, 2 IV, 1 RV, 1 LM, 2 ZM, 1 RM, 2 ST = 12 Spieler, 4-4-2 als Standardtaktik, PlayerSourceRating vorhanden, Ausdauer + Frische gesetzt
Auslosung für 32 Teams erzeugt exakt 16 Erstrundenspiele, keine Freilose, deterministisch (gleicher Seed = gleiche Auslosung)
Jede Runde simulieren → Sieger zieht automatisch in nächste Runde (atomar, kein Duplikat)
Post-Match-Pipeline: Frische, Verletzungen, Statistiken, Noten werden nach Pokalspielen angewendet
Pokalbaum zeigt alle Runden, Ergebnisse als "1:1 n. V." / "1:1 i. E. (5:4)", Sieger hervorgehoben, Link zum Spielbericht
Saisonbezogener Pokalsieger in CupSeason gespeichert (historisch nachvollziehbar)
Ligaspieltage und Pokalrunden überlappen nicht
Out of scope
Freilose (32 Teams = keine nötig; Freilos-Logik bleibt im Service für generische Counts vorhanden, aber ungenutzt)
Setzlisten, regionale Lostöpfe, Heimrecht-Regeln, Wiederholungsspiele
Integration in globalen automatischen Spieltags-Zyklus
Qualifikationsrunden
Echter Spielplan-Kalender mit DFB-Daten
Modellarchitektur
League (competition_type='cup', max_teams=32)
└── CupSeason (competition + season, participants M2M, status, winner_club)
    └── CupRound (round_number, round_code, status, scheduled_date)
        └── CupFixture (bracket_position, home/away_club, winner_club,
                        simulated_match, home/away_goals_90, home/away_goals_et,
                        home/away_penalties, decided_by, is_bye, status)

Ergebnisfelder (exakt entsprechend simulate_ko_match()-Output aus #501):

home_goals_90, away_goals_90 — Ergebnis nach 90 Minuten
home_goals_et, away_goals_et — Tore nur in der Verlängerung
home_penalties, away_penalties — Elfmeterschießen-Tore
decided_by — 'regular_time' | 'extra_time' | 'penalties'
Freilos-Formel (generisch, für beliebige Teilnehmerzahlen)
def calculate_opening_round(n):
    if n < 2:
        raise ValueError("Mindestens 2 Teilnehmer erforderlich")
    target = 1 << (n.bit_length() - 1)   # größte 2er-Potenz ≤ n
    if n == target:
        return {"matches": n // 2, "byes": 0}
    matches = n - target
    byes = target - matches
    return {"matches": matches, "byes": byes}
# 32 → {matches: 16, byes: 0}
# 36 → {matches: 4,  byes: 28}

Steps
League-Modell erweitern — Felder competition_type (Choices: 'league'/'cup', Default 'league') und max_teams (Int, Default 18) hinzufügen. Migration erstellen. is_cup-Property als Alias. Bestehendes League.cup_winner bleibt als Legacy-Feld erhalten, wird aber nicht mehr aktiv genutzt.

Neue Modelle anlegen und migrieren — CupSeason (FK→League, season, participants M2M Club, status Choices setup/running/completed, winner_club FK nullable), CupRound (FK→CupSeason, round_number, round_code, status Choices pending/scheduled/completed, scheduled_date DateField nullable; UniqueConstraint auf cup_season+round_number), CupFixture (FK→CupRound, bracket_position Int, home_club/away_club FK nullable, winner_club FK nullable, simulated_match OneToOne nullable, home/away_goals_90, home/away_goals_et, home/away_penalties Int nullable, decided_by CharField nullable, is_bye Bool, status Choices scheduled/played/bye; UniqueConstraint auf cup_round+bracket_position). Migration erstellen, alle drei Modelle in Admin registrieren.

cup_service.py — generate_dummy_clubs() — Idempotente Factory: Club.objects.get_or_create(name=f"{prefix} #{i}"). Pro Club: PlayerSourceRating anlegen (ausdauer=70, alle Attribute=60, tw_reflexe für TW=72), Freshness-Eintrag (current_freshness=100), Verknüpfung Club→League. Positionskader: 1 TW, 1 LV, 2 IV, 1 RV, 1 LM, 2 ZM, 1 RM, 2 ST. Standardtaktik 4-4-2 via ensure_default_tactic(). Namen: "{prefix} #{i} TW" etc.

cup_service.py — Auslosung draw_cup_round() — seed = stable_seed(f"cup-draw:{cup_season.competition_id}:{cup_season.season}:{round_number}") (stable_seed aus ticker_commentary.py importieren). Teilnehmer stabil sortieren: clubs = sorted(participants, key=lambda c: c.id), dann rng.shuffle(clubs). Freilose via calculate_opening_round(). Bracket-Positionen 1..N aufsteigend zuweisen. CupFixture.objects.get_or_create(cup_round=round, bracket_position=pos) verhindert Duplikate. Freilos-Fixtures: is_bye=True, winner_club=freilos_club, status='bye', kein SimulatedMatch.

cup_service.py — simulate_cup_fixture(fixture) — Ruft simulate_ko_match() auf. Schreibt alle Ergebnisfelder (goals_90, goals_et, penalties, decided_by, winner_club) auf CupFixture. Erstellt SimulatedMatch und verknüpft ihn. Ruft danach dieselben Post-Match-Hooks wie die Liga-Pipeline auf: Frische-Decrement, Verletzungsauswertung, Spielerstatistiken, Sperren-Decrement. Status → 'played'.

cup_service.py — advance_cup_round(cup_round) — Prüft in transaction.atomic() mit SELECT FOR UPDATE, ob alle CupFixtures der Runde status='played' oder 'bye'. Sammelt winner_club-Liste. Prüft ob nächste Runde bereits existiert (CupRound mit round_number+1) → Abbruch bei Duplikat. Erstellt nächste CupRound + draw_cup_round(). Bei Finale (2 Teilnehmer → 1 Spiel → 1 Sieger): setzt cup_season.winner_club + status='completed'.

cup_service.py — schedule_cup_round(cup_round) — Setzt cup_round.scheduled_date: nimmt nächsten freien Dienstag/Mittwoch nach dem letzten SeasonFixture-Datum der beteiligten Clubs (INNER JOIN auf home_club/away_club). Prüft gleichzeitig auf Kollision mit anderen CupRound.scheduled_date. Schreibt Datum auf CupRound (einmal pro Runde, nicht pro Fixture).

Creator Mode: Wettbewerb anlegen — Auf Level-2-Seite (Ligen eines Landes) Button "Neuer Wettbewerb" mit Mini-Formular: Name, Typ (Liga/Pokal), max_teams. POST-Endpunkt creator_competition_create erstellt League-Objekt und leitet zu creator_league_edit weiter. URL: creator/competitions/create/.

Creator-UI: Pokalverwaltung — In creator_league_edit neuer Tab "Pokal" (nur wenn competition_type='cup'): Saison wählen/anlegen, Teilnehmer-Ligen auswählen, Button "Dummy-Clubs generieren", Button "Runde auslosen", Button "Runde simulieren" (simuliert alle offenen Fixtures), Button "Runde abschließen". Spielplan-Tab: zeigt CupFixtures statt SeasonFixtures.

Pokalbaum-Template — URL /competitions/<id>/cup-tree/<season>/, View cup_tree_view. Baut Dict {round_number: [fixtures]}. Template zeigt Runden nebeneinander. Ergebnisanzeige: display_score = "1:1", decision_suffix = "n. V." / "i. E.", penalty_score = "5:4". Sieger-Club hervorgehoben (CSS-Klasse). Link zu SimulatedMatch-Report. Innerhalb 1440px-Design-System.

Tests — game/tests/test_cup_service.py mit ≥ 20 Tests. Pflicht-Tests aus Spec plus: 32 Teams → 16 Spiele/0 Freilose; 36 Teams → 4 Spiele/28 Freilose (calculate_opening_round); 28-Freilos-Clubs kommen alle weiter; kein SimulatedMatch bei Freilos; Finalsieger in CupSeason.winner_club für richtige Saison; neue Saison überschreibt alte CupSeason nicht; Dummy-Kader 4-4-2 valide; erneutes generate_dummy_clubs() erzeugt keine Duplikate; scheduled_date kollidiert nicht mit Ligaspiel; gleichzeitige advance_cup_round()-Aufrufe erzeugen keine doppelte nächste Runde (Transaktion); leere Teilnehmerliste wird abgewiesen.
