Minuten nicht unnötig aus Wechseln rekonstruieren

Seit Dynamic Lineup V1 werden die Einsatzfenster bereits auf die Spielerzeilen geschrieben:

on_minute
off_minute

Diese Werte sollten primär verwendet werden.

minutes_played = max(
    0,
    min(match_end, off_minute) - max(0, on_minute),
)

Nur für ältere Report-Daten ohne diese Felder sollte die Wechselrekonstruktion als Fallback verwendet werden.

Zusätzlich müssen Platzverweise berücksichtigt werden. Ein Spieler, der in Minute 25 Rot sieht, darf nicht als 90-Minuten-Spieler gelten.

Priorität:

1. on_minute/off_minute aus Spielerzeile
2. Wechselereignisse
3. Rot/Gelb-Rot als vorzeitiges off_minute
4. Fallback: Starter 0–90
8. Nur vollständigen Spieltag verwenden

Nicht einfach den höchsten Spieltag mit mindestens einem simulierten Spiel nehmen.

Sonst könnte nach dem ersten Freitagsspiel eine Elf des Spieltags aus nur zwei Mannschaften erscheinen.

Verwendet werden sollte:

der höchste vollständig abgeschlossene Spieltag der Liga und Saison

Beispielsweise:

fixtures = SeasonFixture.objects.filter(
    season=season,
    league=league,
    matchday=matchday,
)

is_complete = (
    fixtures.exists()
    and not fixtures.filter(simulated_match__isnull=True).exists()
)

Falls Nachholspiele eine Rolle spielen, muss die Definition gegebenenfalls über den Status played/completed erfolgen.

9. Vereinswappen benötigt keinen Player-ORM-Lookup

Da bekannt ist, aus welcher Fixture-Seite die Spielerbewertung stammt, ist auch der Verein bekannt:

home_ratings → fixture.home_club
away_ratings → fixture.away_club

Damit können direkt gespeichert werden:

{
    "club_id": fixture.home_club_id,
    "club_name": fixture.home_club.name,
    "crest": fixture.home_club.crest_static_path,
}

Ein zusätzlicher Lookup über Player.objects.get() ist für das Wappen nicht nötig.

Das vermeidet N+1-Abfragen und funktioniert auch bei historischen oder inzwischen transferierten Spielern korrekt. Für die Elf des damaligen Spieltags zählt der Verein aus der Fixture, nicht der aktuelle Verein des Spielers.

10. Gleichstände deterministisch entscheiden

Bei gleicher Note sollte die Auswahl nicht von der Datenbankreihenfolge abhängen.

Empfohlene Reihenfolge:

Note aufsteigend
Tore absteigend
Vorlagen absteigend
Minuten absteigend
exakter Positionsfit vor kompatiblem Fit
Spieler-ID aufsteigend

Falls Tore und Vorlagen noch nicht direkt in den Rating-Dicts stehen, können sie einmal aus den Matchereignissen aggregiert werden.

Empfohlener Formationskatalog

Diese sieben Formationen sind ausreichend:

FORMATION_PRIORITY = [
    "4-4-2",
    "4-2-3-1",
    "4-3-3",
    "3-5-2",
    "5-3-2",
    "4-5-1",
    "3-4-3",
]

Jede Formation bekommt:

eindeutige Slotnamen,
eine grafische Linie,
X-/Y-Koordinaten für das Pitch-Layout,
erlaubte exakte und kompatible Positionen.

Beispiel:

FORMATION_SLOTS = {
    "4-4-2": [
        {"slot": "GK", "line": "gk", "x": 50, "y": 88},
        {"slot": "LB", "line": "def", "x": 15, "y": 68},
        {"slot": "LCB", "line": "def", "x": 38, "y": 72},
        {"slot": "RCB", "line": "def", "x": 62, "y": 72},
        {"slot": "RB", "line": "def", "x": 85, "y": 68},
        # ...
    ],
}

Mit festen Koordinaten wird die Darstellung garantiert symmetrisch. Eine reine Flexbox-Zeile reicht dafür nur bedingt.
